# GitHub Copilot Dispatch — V1.1 Specification: PR Review & Approval

> Version: 1.1.0-draft
> Last updated: 2026-03-29
> Status: In Development
> Depends on: V1.0 (Agent Sessions + Auth)

---

## 1. Feature Overview

V1.1 adds full **Pull Request review capabilities** to Copilot Dispatch. Users can browse open PRs, inspect diffs and CI/CD status, read comments, and take action (approve, request changes, comment, merge) — all from the Apple Watch.

### 1.1 User Stories

- As a developer, I want to see open PRs across my repos so I can triage on the go
- As a reviewer, I want to see diff stats (+/- lines, changed files) so I can gauge PR scope
- As a reviewer, I want to see CI/CD check results so I know if the PR is safe to merge
- As a reviewer, I want to read PR comments so I understand the discussion context
- As a reviewer, I want to approve, request changes, or comment on a PR from my Watch
- As a maintainer, I want to merge a PR from my Watch when all checks pass

## 2. API Specification

Base URL: `https://<backend-host>/api`

All endpoints require `Authorization: Bearer <github_access_token>`.

### 2.1 List Pull Requests

#### `GET /api/repos/:owner/:repo/pulls`

List pull requests for a repository.

**Path params:**
- `owner` — Repository owner (user or org)
- `repo` — Repository name

**Query params:**
| Param   | Type   | Default | Description                          |
| ------- | ------ | ------- | ------------------------------------ |
| `state` | string | `open`  | Filter: `open`, `closed`, `all`      |
| `limit` | number | `20`    | Max results to return                |

**Response `200`:**
```json
{
  "pullRequests": [
    {
      "number": 42,
      "title": "Fix utils test edge case",
      "author": "copilot[bot]",
      "branch": "copilot/fix-42",
      "baseBranch": "main",
      "state": "open",
      "additions": 15,
      "deletions": 3,
      "changedFiles": 2,
      "ciStatus": "success",
      "mergeable": true,
      "draft": false,
      "createdAt": "2026-03-29T00:05:00Z",
      "updatedAt": "2026-03-29T00:10:00Z"
    }
  ]
}
```

### 2.3 Submit Review

#### `POST /api/repos/:owner/:repo/pulls/:number/review`

Submit a review on a pull request.

**Request:**
```json
{
  "event": "APPROVE",
  "body": "LGTM! 👍"
}
```

| Field   | Type   | Required | Description                                        |
| ------- | ------ | -------- | -------------------------------------------------- |
| `event` | string | Yes      | `APPROVE`, `REQUEST_CHANGES`, or `COMMENT`         |
| `body`  | string | No       | Review comment (required for `REQUEST_CHANGES`)    |

**Response `200`:**
```json
{
  "status": "review_submitted",
  "event": "APPROVE"
}
```

---

### 2.4 Merge Pull Request

#### `PUT /api/repos/:owner/:repo/pulls/:number/merge`

Merge a pull request.

**Request:**
```json
{
  "mergeMethod": "squash"
}
```

| Field         | Type   | Default  | Description                       |
| ------------- | ------ | -------- | --------------------------------- |
| `mergeMethod` | string | `merge`  | `merge`, `squash`, or `rebase`    |

**Response `200`:**
```json
{
  "status": "merged",
  "sha": "abc123def456"
}
```

**Response `409` (not mergeable):**
```json
{
  "error": "MERGE_CONFLICT",
  "message": "Pull request is not mergeable",
  "statusCode": 409
}
```

### 2.5 Get CI/CD Check Status

#### `GET /api/repos/:owner/:repo/pulls/:number/checks`

Get CI/CD check run status for the PR's head commit.

**Response `200`:**
```json
{
  "state": "success",
  "checks": [
    {
      "name": "CI / test",
      "status": "completed",
      "conclusion": "success"
    },
    {
      "name": "CI / lint",
      "status": "completed",
      "conclusion": "success"
    },
    {
      "name": "Deploy Preview",
      "status": "in_progress",
      "conclusion": null
    }
  ]
}
```

**`state` values:**
| Value     | Meaning                                     |
| --------- | ------------------------------------------- |
| `success` | All checks passed                           |
| `failure` | At least one check failed                   |
| `pending` | Checks are still running                    |
| `neutral` | No checks configured or all neutral         |

## 3. Data Models

### 3.1 PullRequest

| Field          | Type           | Description                              |
| -------------- | -------------- | ---------------------------------------- |
| `number`       | `number`       | PR number                                |
| `title`        | `string`       | PR title                                 |
| `author`       | `string`       | Author login                             |
| `branch`       | `string`       | Head branch name                         |
| `baseBranch`   | `string`       | Base branch name                         |
| `state`        | `PRState`      | `open`, `closed`, or `merged`            |
| `additions`    | `number`       | Lines added                              |
| `deletions`    | `number`       | Lines deleted                            |
| `changedFiles` | `number`       | Number of files changed                  |
| `ciStatus`     | `string\|null` | Combined CI status                       |
| `mergeable`    | `bool\|null`   | Whether the PR can be merged             |
| `draft`        | `boolean`      | Whether this is a draft PR               |
| `createdAt`    | `string`       | ISO 8601 timestamp                       |
| `updatedAt`    | `string`       | ISO 8601 timestamp                       |

### 3.2 PullRequestDetail (extends PullRequest)

| Field      | Type                 | Description                    |
| ---------- | -------------------- | ------------------------------ |
| `body`     | `string\|null`       | PR description (markdown)      |
| `files`    | `PullRequestFile[]`  | Changed files list             |
| `checks`   | `CheckRun[]`         | CI/CD check runs               |
| `comments` | `PRComment[]`        | PR conversation comments       |

### 3.3 PullRequestFile

| Field       | Type     | Description                                    |
| ----------- | -------- | ---------------------------------------------- |
| `filename`  | `string` | File path                                      |
| `status`    | `string` | `added`, `modified`, `removed`, `renamed`      |
| `additions` | `number` | Lines added in this file                       |
| `deletions` | `number` | Lines deleted in this file                     |

### 3.4 CheckRun

| Field        | Type            | Description                          |
| ------------ | --------------- | ------------------------------------ |
| `name`       | `string`        | Check/job name                       |
| `status`     | `string`        | `queued`, `in_progress`, `completed` |
| `conclusion` | `string\|null`  | `success`, `failure`, `neutral`, etc.|

### 3.5 PRComment

| Field            | Type     | Description                |
| ---------------- | -------- | -------------------------- |
| `id`             | `number` | Comment ID                 |
| `author`         | `string` | Commenter login            |
| `authorAvatarUrl`| `string` | Commenter avatar URL       |
| `body`           | `string` | Comment text               |
| `createdAt`      | `string` | ISO 8601 timestamp         |

## 6. Polling Strategy

| Context                    | Poll Interval | Endpoint                                       |
| -------------------------- | ------------- | ---------------------------------------------- |
| PR list visible            | 10 seconds    | `GET /api/repos/:owner/:repo/pulls`            |
| PR detail visible          | 10 seconds    | `GET /api/repos/:owner/:repo/pulls/:number`    |
| After submitting review    | Immediate     | Refresh PR detail                              |
| After merging              | Immediate     | Refresh PR detail (state → merged)             |

PR polling is slower than session polling (10s vs 3s) since PRs change less frequently.

## 8. Error Handling

| Scenario                    | Behavior                                         |
| --------------------------- | ------------------------------------------------ |
| PR not found                | Show "PR not found" error, back to list          |
| Merge conflict              | Show "Not mergeable — conflicts exist" alert     |
| Review submission fails     | Show error toast, keep form state                |
| No checks configured        | Hide CI section, show "No checks" text           |
| Rate limited                | Show "Too many requests, try again later"        |
| Network timeout             | Show "Unable to connect" with retry button       |

| Merge           | `octokit.rest.pulls.merge()`                       |

### 9.2 Route Structure

```
src/routes/pulls.ts

Router mounted at: /api/repos/:owner/:repo/pulls
All routes use requireAuth middleware

GET    /                    → listPullRequests
GET    /:number             → getPullRequestDetail
POST   /:number/review      → submitReview
PUT    /:number/merge       → mergePR
GET    /:number/checks      → getPRChecks
```

### 9.3 Merged State Detection

GitHub API returns `state: 'closed'` for both closed and merged PRs. To distinguish:
- Check `merged_at` field: if present, state is `merged`
- Or check `pull.merged` boolean

## 11. Assignees & Reviewer Requests

### 11.1 Overview

PR detail view includes management of assignees and reviewers. Users can add/remove assignees, request reviews from collaborators, and specifically request a **Copilot code review**.

### 11.2 API Endpoints

#### `POST /api/repos/:owner/:repo/pulls/:number/assignees`

Add assignees to a PR.

**Request:**
```json
{
  "assignees": ["octocat", "copilot[bot]"]
}
```

**Response `200`:**
```json
{
  "status": "assignees_updated",
  "assignees": [
    { "login": "octocat", "avatarUrl": "https://..." }
  ]
}
```

#### `DELETE /api/repos/:owner/:repo/pulls/:number/assignees/:login`

Remove an assignee from a PR.

**Response `200`:**
```json
{
  "status": "assignee_removed"
}
```

#### `POST /api/repos/:owner/:repo/pulls/:number/reviewers`

Request reviewers for a PR. Supports requesting Copilot (`"copilot"` maps to `"copilot[bot]"`).

**Request:**
```json
{
  "reviewers": ["octocat", "copilot"]
}
```

**Response `200`:**
```json
{
  "status": "reviewers_requested",
  "reviewers": [
    { "login": "octocat", "avatarUrl": "https://..." }
  ]
}
```

#### `DELETE /api/repos/:owner/:repo/pulls/:number/reviewers/:login`

Remove a requested reviewer.

**Response `200`:**
```json
{
  "status": "reviewer_removed"
}
```

#### `GET /api/repos/:owner/:repo/collaborators`

List repo collaborators for the user picker.

**Response `200`:**
```json
{
  "collaborators": [
    { "login": "octocat", "avatarUrl": "https://..." },
    { "login": "copilot[bot]", "avatarUrl": "https://..." }
  ]
}
```
